# 시각장애용 안내 문구 정책

## 목표

업체·점역사 제작 **참고 BRF**에 들어 있는 시각장애 응시자용 안내·머리말·꼬리말·유의 문구를,  
생성 BRF에도 **같은 역할·비슷한 양식**으로 넣어 최종적으로 참고본과 일치시킨다.

지금은 비교기(`exam_diff`)가 참고본 안내를 `expected_guidance`로 **허용 차이** 처리한다.  
이는 본문 정합 작업 중의 잠정 조치이며, **최종 상태에서는 안내도 일치 대상**이다.

## 안내의 종류 (참고본에서 관찰·분류)

실제 문구는 Phase 0 노트와 참고 BRF에서 확정한다. 전형적 구분:

| 종류 | 예시 역할 | 삽입 위치 (안) |
|------|-----------|----------------|
| 시험 머리말 | 학년도·교시·영역명 | 1면 상단 (layout 머리말과 정합) |
| 이용 안내·유의 | 점자 문제지 사용법, 답안·넘김 안내 | 본문 문항 전 preamble |
| 구간 안내 | 지문/보기 경계 보조 설명 | 해당 PassageGroup·ExampleBox 전후 |
| 꼬리말·종료 | 끝·수고 등 | 문서 말미 |

PDF 비장애본에 없는 문장이 참고 BRF에만 있는 경우가 많다. → **템플릿/규칙으로 생성**해야 한다.

## 원문 시각 강조(밑줄 등) → 점자 추가 정보

### 취지

비장애 PDF의 **밑줄·강조**는 수능 국어에서 지문·발문의 핵심 구간을 가리키는 경우가 많다.  
시각장애인 응시자에게도 이 정보는 **생략하면 안 되는 추가 정보**다.

다만 목표는 웹/진단 UI에 밑줄을 예쁘게 그리는 것이 아니다.  
원문을 plain text로만 흘려 보내는 경로와 분리하고, **시각장애용 안내·양식을 새로 삽입하는 단계(본 문서의 계층)** 에서  
«밑줄 시작/끝» 등 **점자 관례에 맞는 안내 문구·표기**로 전달한다.

현재 PDF 추출은 드로잉 밑줄을 `<u>…</u>` 마커로 남기고, 보기 박스는 표선 행으로,
본문·원문자 배치는 PDF 읽기 순서를 따른다(아래 원문자를 본문에 끌어올리지 않음).
점역은 `,-`/`-'`·`7a7` 경로를 쓴다.
안내 문구(Guidance) 삽입은 별도 레이어로 남는다.

### 예상 기술 방법

1. **감지 (PDF → 물리/의미 메타)**  
   - PyMuPDF `get_text("dict")`의 span `flags`(underline 비트)와, 밑줄이 **선 드로잉**으로만 있는 경우 `page.get_drawings()` 등으로 텍스트 bbox와 교차.  
   - 결과를 `PdfSpan`/`PdfBlock` 또는 Exam 노드의 **구간 오프셋 메타**(예: `emphasis: underline`, `char_start`/`char_end`)로 보존.  
   - 웹 plain text 미리보기 개선은 필수가 아님(진단용이면 태그·목록만으로도 충분).

2. **의미 구조에 실기**  
   - Exam 빌더가 해당 텍스트를 담은 Passage/Question 등에 emphasis 구간을 붙이거나,  
   - 안내 삽입기가 읽을 수 있는 별도 `EmphasisSpan` 목록을 파이프라인 결과에 실음.

3. **안내·점역으로 내보내기 (본 정책과 동일 레이어)**  
   - 참고 BRF에서 쓰는 관례를 Phase 0에 기록한 뒤(예: 밑줄 전후 안내 셀·괄호형 표기),  
   - Guidance/Instruction 삽입 또는 점역 토큰 단계에서 **같은 양식**으로 생성.  
   - 머리말·유의 템플릿과 같이 `rules/`·`profiles/` 쪽에 관례 문자열을 두고 회귀.

4. **검수**  
   - 삽입 전: 밑줄 관련 참고 구간은 `expected_guidance`(또는 별도 expected_emphasis)로 허용 가능.  
   - 삽입 후: 셀/`exam_diff` 정합 대상에 포함.

### 하지 않을 것 (의도적)

- 제품 사용자 모드에서 “밑줄 있는 HTML 원문 미리보기”를 우선 구현하지 않는다.  
- 밑줄만 단독 기능으로 UI에 붙이지 않고, **안내 삽입·참고 BRF 양식 일치**와 한 묶음으로 둔다.

## 설계 방향

1. **소스 of truth**  
   - 단기: `docs/`에 묵자 원문 + 참고 BRF ASCII 샘플 기록.  
   - 구현: `rules/` 또는 `profiles/` 옆 템플릿(YAML/텍스트) + 점역 파이프라인.
2. **파이프라인 삽입점**  
   - Exam 트리에 `Instruction`/`Guidance` 노드를 넣거나,  
   - Layout 직전·직후에 고정 시퀀스를 prepend/append.  
   - 머리말은 기존 `header_format`과 중복되지 않게 한곳으로 모은다.
3. **시험 공통 vs 회차 고유**  
   - 공통 유의문은 템플릿.  
   - 회차 제목(학년도·월·고2 등)은 PDF Header/메타에서 채움.
4. **비교 전환**  
   - 삽입 구현 전: `expected_guidance` 유지.  
   - 삽입 구현 후: 안내 구간도 `compare` 셀 정합 대상. 불일치는 오류.

- [ ] 회귀 테스트: 안내 있는/없는 fixture
- [ ] 밑줄 등 강조: PDF 감지 → 메타 → 점자 안내 표기 (참고 BRF 관례 기록 포함)
- [ ] 강조 구간 fixture + 비교 전환 (expected → 정합 대상)

## 현재 코드와의 관계

- `exam_diff._GUIDANCE_INK` / preamble 분류: 진단용.
- `common` / nav의 `Instruction` 타입: 태그·탐색용으로만 존재할 수 있음 — 생성 경로에 아직 본격 미연결.
- 본문 문항 정합 작업과 **병행 가능**하나, 셀 일치율 목표에는 안내 삽입 완료가 포함된다.
- 밑줄·강조의 점자 안내화는 위 «원문 시각 강조» 절. 단기 PDF/웹 표시 보완과 혼동하지 않는다.
